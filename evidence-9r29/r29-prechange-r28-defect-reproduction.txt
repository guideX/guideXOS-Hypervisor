Live ACPICA failure reproduced before the change
------------------------------------------------
Using the unchanged R28 firmware build, the same authenticated ISO, and the
R24 checkpoint, a bounded strict continuation of 59,000,000 successful slots
ended at cycle 837197459. The output is
evidence-9r29/r29-r28-original-repro-59m.console.log. It observes DOEXIT after
the same Linux init-task BUG path; panic is not claimed within this 59M window.
The ACPI root page at that boundary is
evidence-9r29/r29-r28-original-acpi-page-59m.bin and has the same bytes/hash as
the one-slot restore snapshot.

The existing authenticated R28 probes identify the failing chain and live
object: acpi_tb_initialize_facs -> acpi_get_table_by_index(index 1,
ACPI_TABLE_INDEX_FACS) -> acpi_tb_verify_table at descriptor VA
0xE000000000B29360. The table descriptor's 32 bytes were read at the matching
IA-64 kernel linear-map physical address 0x00B29360 after the bounded replay;
evidence-9r29/r29-r28-original-facs-descriptor-59m.bin is 32 zero bytes,
SHA-256 66687AADF862BD776C8FC18B8E9F8E20089714856EE233B3902A591D0D5F2925.
With the Linux v3.2 descriptor layout, address at +0 is 0, table pointer at +8
is null, length at +16 is 0, and origin flags at +25 are 0. The guest trace
also reads the null pointer and flags at the authenticated caller site. No
acpi_os_map_memory call occurs for this lookup. acpi_tb_verify_table returns
status 4 (AE_NO_MEMORY) at cycle 836763185; acpi_enable_subsystem propagates it
at cycle 836763350. This is the empty descriptor path, not evidence of RAM
exhaustion or an attempted mapping failure.

R28 then aborts ACPI initialization; acpi_bus_type.p remains null. The later
acpi_pci_root_driver registration reaches Linux's real driver_register BUG_ON,
followed by die(), do_exit(SIGSEGV), and the init-task panic. The complete
accepted trace/disassembly remains in evidence-9r28 and is cross-indexed by its
verified manifest.

Old EFI memory-map classification
---------------------------------
R24's preserved EFI evidence reports [0x1FDB2000, 0x1FDB3000) as the PAL-code
page. The old RSDP, RSDT, XSDT, MADT, SAL structures and EFI configuration
entries shared that page. R29 therefore moves ACPI tables to dedicated pages:
ACPI reclaim for RSDP/root/MADT/FADT/DSDT, and ACPI NVS for the writable FACS.
