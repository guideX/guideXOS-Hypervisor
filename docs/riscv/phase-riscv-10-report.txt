Timer and virtual-time behavior
-------------------------------
The timer reuses the existing deterministic mtime/mtimecmp MMIO model. One
virtual timer tick advances per retired guest instruction. WFI stops normal
retirement; the test harness explicitly advances a bounded number of virtual
ticks to the next requested deadline, then resumes architectural interrupt
selection. No host wall clock and no timer-to-STIP host shortcut are used.
mtime comparison is unsigned mtime >= mtimecmp; the 64-bit counter wraps
modulo 2^64. The SBI UINT64_MAX disarm request is accepted by the model.
Pending MTIP is derived from the timer comparison even while MTIE is masked.
Reading and writing the mapped 64-bit registers is exercised by OpenSBI;
invalid address, width, size, and alignment cases fail explicitly.

OpenSBI execution and interrupt evidence
-----------------------------------------
The supervisor runs with Sv39 enabled. It checks hart/FDT inputs, probes SBI
TIME through SBI Base, reads time, and issues real S-mode ECALL instructions.
There is no host SBI provider attached to this run. The test recorded nine
guest SBI ECALLs: Base version query, TIME extension probe, unsupported TIME
FID 1 (returned -2/SBI_ENOTSUPP), and six TIME FID 0 calls. The six absolute
timer values cover an already-expired request, a future request, a masked
reprogrammed request, two independent rearms, and UINT64_MAX disarm. Each
TIME call returned success and its comparator update was observed as a real
guest M-mode MMIO store.

The expired request caused an architectural MTIP trap with mcause
0x8000000000000007; OpenSBI's M-mode vector was 0x80000448, and the captured
M-mode trap PC was 0x802000FC. OpenSBI's actual SBI timer code clears STIP
when scheduling and services MTIP by presenting STIP through CSR state. Three
distinct delegated supervisor timer traps were recorded with scause
0x8000000000000005, stvec 0x802001B0, sepc 0x80200194, and sstatus 0x120.
Each supervisor handler increments the guest-memory event counter only after
handler entry, reprograms the next deadline through SBI TIME, and returns by
SRET at 0x802002B0 to 0x80200194. The test also verifies STIP clearing when a
future deadline is programmed while both SIE and STIE are masked.

The bounded run recorded 4 MTIP entries, 3 STIP handler entries, 3 WFI calls,
3 timer-driven WFI wakes, and 3 SRET returns. Each wake was caused by a
separately advanced deadline. The trace retains bounded boot and recent
instruction windows, plus SBI ECALL, comparator MMIO, M-mode trap, supervisor
trap, WFI, SRET, and completion records with guest PC, mode, instruction,
cause, and relevant CSR state. The run completed in 4,102,440 emulator steps.

Remaining platform and Linux blockers
-------------------------------------
This remains a deterministic one-hart platform profile. It has no PLIC,
APLIC, IMSIC, device external interrupts, SMP, PMP isolation, full UART, or
RV64C/F/D/V execution. Linux boot was explicitly out of scope and no Linux
image loader or Linux entry-register/paging contract was added. A future Linux
target still needs a deliberately selected firmware/kernel ISA profile, a
Linux Image loader and entry handoff, sufficient RAM and reservations, and the
device/external-interrupt support required by its chosen root-device and
console configuration. This result is not a QEMU virt compatibility claim.

Recommended RISCV-11 scope
--------------------------
Add one narrowly selected external-interrupt controller/device path with
architectural delegation and bounded end-to-end guest evidence, while keeping
the single-hart deterministic model. Use that to validate the next FDT and
interrupt contracts before considering Linux. Keep PMP, SMP, Linux Image
loading, and wider device emulation as separately scoped work.
