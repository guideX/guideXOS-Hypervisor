Initialization and task lifecycle
---------------------------------
Milestones were selected from the actual pinned vmlinux symbol table. The
observer records guest PC, post-handoff retirement, privilege, registers,
CSRs, caller evidence when directly validated, and entry/return classification.
Function entry alone is not reported as subsystem completion. Linux v6.12
source reference: https://github.com/torvalds/linux/blob/v6.12/init/main.c

Observed entries include start_kernel, setup_arch, sched_init, trap_init,
timekeeping_init, time_init, rest_init, kernel_init, kernel_init_freeable,
kthreadd, do_one_initcall, and populate_rootfs. The symbol is reached in
S-mode with satp=0x80000000000812ef. sched_init, setup_arch, trap_init,
timekeeping_init, and time_init have return observations. rest_init,
kernel_init, kernel_init_freeable, and kthreadd are entry-only at the bounded
horizon. populate_rootfs entered from do_one_initcall at 25,326,062 retired
instructions and returned at 25,328,254 with a0=0. This is a function return
milestone; it does not prove a mounted root filesystem or started userspace.

The first captured do_one_initcall target was compat_mode_detect. In the
bounded detail set, 256 callback entries have matching returns: 249 returned
zero and 7 returned a nonzero value. The aggregate entry counter observed 364
do_one_initcall entries; 108 later details were not retained after the
per-symbol cap. No claim is made about the return status of those unretained
calls. driver_probe_device and really_probe each had 10 observed entries and
returns; these calls are not treated as proof that every device bound
successfully.

The pinned build has no standalone context_switch symbol. The scheduler path
is observable through schedule, __schedule, and RISC-V __switch_to. The first
captured switch entered __switch_to at 12,077,065 post-handoff retirements and
selected the task later observed entering kernel_init. The next selected task
was observed entering kthreadd. For each of the 512 retained switch records,
the previous task pointer matched tp before the switch, the selected task
pointer differed, tp after the switch matched the selected pointer, sp
changed, and execution exited __switch_to. All 512 retained events therefore
demonstrate completed distinct task switches. The event detail cap dropped
809 subsequent switch details; those dropped events are not included in the
512-event completion statement. Linux v6.12 RISC-V switch source reference:
https://github.com/torvalds/linux/blob/v6.12/arch/riscv/include/asm/switch_to.h

The evidence does not show entry into do_pre_smp_initcalls, do_basic_setup,
do_initcalls, prepare_namespace, run_init_process, try_to_run_init_process,
kernel_execve, init_post, cpu_startup_entry, or default_idle_call by 80M.
Some of these functions have symbols in vmlinux but no observed entry; others
are absent from this build. kernel_init has not been shown to return from its
initialization path, and no userspace process was observed.

The panic/Oops marker scan observed no Linux panic marker.

At 80M, Linux made 3,497 SBI ecall requests; all returned to and resumed S-mode
with result evidence. 3,445 returned 0. The 52 nonzero results were all SBI
PMU EID 0x504d55 calls: 50 FID 2 and one FID 7 returned
SBI_ERR_NOT_SUPPORTED (-2), and one FID 1 returned SBI_ERR_INVALID_PARAM
(-3). The 3,401 SBI TIME calls all returned success. There were
1,699 machine timer and 1,699 supervisor timer interrupts; each observed
handler returned. The 10 MHz virtual mtime advanced one tick per retired guest
instruction. At the cap, mtime is 0x58030a3; mtimecmp is 0x580691f.

Trap accounting records 10,929 non-retiring trap transitions and 10,928
matched handler entries and returns. Active handlers at stop: zero. Maximum
nesting: two. Largest handler: 6,012 instructions. No trap event details were
dropped. The total is 75,967,555 S-mode Linux retirements plus 4,032,445
M-mode OpenSBI retirements, exactly 80,000,000. Of the S-mode total,
70,344,307 are normal Linux instructions and 5,623,248 are handler
instructions.

RISCV-25 recommendation
-----------------------
Continue from the real 80M guest state with a separately bounded run only
after reviewing this frontier. Prioritize observing the remainder of
kernel_init_freeable and the transition into later initcalls or namespace/init
preparation. Determine from guest execution whether the next requirement is
an absent root filesystem or device, ordinary initialization work, or a
specific architectural/platform behavior. Keep Linux, its config, RAM, PMP,
and firmware unchanged until guest evidence demonstrates a concrete blocker.
Do not infer Linux boot completion from retirement count or these task
switches.
