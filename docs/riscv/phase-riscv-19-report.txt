Reproduced RISCV-18 entry and BSS completion
--------------------------------------------
The authentic OpenSBI run retired 12,287,177 steps, including 12,287,139
M-mode instructions, and made the real MRET handoff. At Linux entry the CPU
was S-mode with PC=0x80200000, a0=0, a1=0x82200000, and satp=0. No host SBI
provider was attached. The authentic Image header JAL was retired.

The fresh run reproduced the 100,000-instruction RISCV-18 frontier exactly:
the last retired PC was 0x8020010c and the next instruction at 0x80200104 was
`sd zero,0(a3)`. At that point a3=0x81326188, a4=0x8133b3a8, and the guest had
retired 33,329 stores into BSS.

The linked symbols identify BSS as virtual range
[0xffffffff810e5000,0xffffffff8113b3a8), which maps to physical range
[0x812e5000,0x8133b3a8). The guest itself executed all 44,149 doubleword
stores, reached a3=a4=0x8133b3a8, took the loop exit at Image PC 0x80200110,
and retired beyond the loop. The last guest store targeted 0x8133b3a0. A
post-exit verification found every byte zero; SHA-256 of the range was

Final bounded frontier and counters
-----------------------------------
The staged total-retirement targets were 100,000, 250,000, 1,000,000,
5,000,000, and 20,000,000 post-handoff guest instructions. The same CPU and
guest RAM continued between stages. The final run made 14,373,535 step calls
and retired 14,373,245 instructions: 14,303,690 S-mode Linux instructions and
69,555 authentic M-mode OpenSBI handler instructions. Trap-handler work had a
separate 250,000-instruction budget; its 250,001st counted instruction
triggered the stop. The independent trap-event budget was 4,096.

The final PC was 0x80019194 in M-mode, at `slli x19,x19,2`, within the pinned
firmware symbol `sbi_trap_handler` (symbol address 0x80019134). `addr2line` on
the pinned OpenSBI ELF maps this to /lib/sbi/sbi_trap.c:327. The immediate
frontier state had mcause=9 (S-mode ECALL), mepc=0xffffffff8000a56c,
mstatus=0x920, satp=0x80000000000812ef, and the last recorded supervisor
timer interrupt in scause/sepc. The stop classification is
`trap_handler_instruction_budget`; this is an execution-policy frontier, not
an architectural fault or an unsupported Linux instruction.

The run recorded 290 trap events: 153 supervisor ECALLs, 136 interrupts, and
the single expected Sv39 alias page fault. All 153 ECALLs reached the real
OpenSBI M-mode vector; the host SBI provider remained absent. The bounded
event trace shows machine timer cause 7 and supervisor timer cause 5. The
final timer count advanced deterministically from 12,287,139 to 26,660,384,
matching the post-handoff retirement delta. PMP entries and the final FDT

Implementation and regressions
------------------------------
No production CPU, Sv39, PMP, OpenSBI, or Linux code was changed. The narrow
RISCV-19 changes add a separate CTest continuation target and bounded evidence
capture. Interrupts are serialized with their architectural interrupt cause,
separately from synchronous exception codes; this avoids the overlapping
numeric cause values from being mislabeled as load/store faults.
