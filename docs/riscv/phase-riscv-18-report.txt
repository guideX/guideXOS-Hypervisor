Image header and memory plan
----------------------------
The parser follows the 64-byte v0.2 header in upstream arch/riscv image.h.
code0=0x0d40006f (uncompressed JAL x0,+0xd4); code1=0. text_offset=0x200000;
image_size=18,068,392; flags=0; version=2; reserved fields=0;
deprecated magic=0x0000005643534952; magic2=0x05435352 (RSC, 0x05).
The deprecated magic may be absent when the modern magic2 is present.

Load address and entry: 0x80200000, 2 MiB from the 0x80000000 RAM base.
Initial branch target: 0x802000d4, verified inside the effective Image.
File-backed extent: [0x80200000, 0x812e4d50); effective extent:
[0x80200000, 0x8133b3a8). The 353,880-byte tail is zero-filled by the loader.
The Image and its complete effective footprint fit in [0x80000000,0x84000000).
FDT: 0x82200000, 12,288-byte protected capacity; post-OpenSBI FDT is 8,174
bytes (SHA-256 580e8235e4c870bd79ae9348e4a8bdca8d999e1c394efe2c773a19d886c14475).
RAM remaining unreserved after the Image and firmware/FDT ranges is 46,931,032
bytes. The eventual Linux runtime allocation footprint is not known from the
raw Image header and is not claimed here.

The Linux profile reserves resident OpenSBI text [0x80000000,0x80080000),
OpenSBI data/scratch [0x80080000,0x800a0000), the protected slot gap
[0x800a0000,0x80200000), and FDT [0x82200000,0x82203000). It drops the
RISCV-17 test payload, page-table, result, and stack reservations. The Linux
Image itself is not declared reserved or no-map. The loader validates all
half-open ranges, overflow, RAM and firmware overlap, active FDT capacity,
reservation conflicts, FW_JUMP equality, PMP first-match coverage, and CPU
memory before staging a single contiguous transactional write. The staged
effective-size tail is zeroed; failed writes attempt memory rollback and do not
change CPU state.

Linux device tree and PMP
------------------------
The separate platform DTS/DTB advertises exactly one enabled hart 0, the
implemented RV64IMA_Zicsr ISA and standard extension properties, Sv39, 64 MiB
RAM, 10 MHz timebase, UART0/1, 96-source PLIC, and firmware-owned ACLINT timer
registers. It advertises no extra harts, storage, networking, PCI, or virtio.
The fixed-up OpenSBI FDT validates with the boot hart enabled, chosen UART0
console, expected device addresses and interrupt contexts, ACLINT disabled to
S-mode, and the four firmware/FDT reservations above.

The observed StandardPmp16 state has 14 active entries and entries 14–15 OFF.
Entries 0–1 deny OpenSBI data/scratch and text; 2–5 preserve the two duplicate
ACLINT mtimecmp/mtime deny entries; 6–7 grant UART0/1 read/write; 8 grants the
2 MiB Linux RAM window RWX; 9 grants PLIC read/write; 10–13 grant the 4, 8,
16, and 32 MiB RAM windows RWX. Config bytes are 0x18 for deny entries, 0x1b
for MMIO read/write, and 0x1f for RAM RWX. There is no S/U catch-all. The
entry instruction matches PMP entry 8 and is executable. The full effective
table is recorded in riscv-pmp-effective-v1.json.

The real firmware banner was observed. The emulator executed 12,287,177

handoff. MMIO was bounded at 8,814 observed events; the retained trace cap is

At the first Linux entry, the production RV64CPU is in S-mode at PC
0x80200000 with a0=0, a1=0x82200000, satp=0. The first fetched and retired
instruction bytes match the raw Image header's JAL x0,+0xd4. The next target
0x802000d4 matches upstream vmlinux `_start_kernel`. No host-side SBI provider
intercepts the firmware path.

Linux ran for a bounded 100,000 retired instructions with zero Linux traps,
interrupts, or SBI ECALLs. Its initial startup entered the BSS-clear loop. At
the budget frontier the last retired PC was 0x8020010c (blt x13,x14,-8); the
next fetched but unexecuted instruction was at 0x80200104, raw word 0x0006b023,
`sd zero,0(a3)`. Its physical fetch address was 0x80200104 and PMP entry 8
allowed execution. This is a progress/budget frontier, not an unsupported
instruction or fault. The linked vmlinux disassembly at VMA
0xffffffff80000104 contains the same instruction bytes and BSS loop. Trace
head/tail retention is 64 entries each; the Linux budget is 100,000 steps and
repeated-PC threshold is 100,000. Linux initialization, console output,
scheduler, and complete boot were not established or required.
