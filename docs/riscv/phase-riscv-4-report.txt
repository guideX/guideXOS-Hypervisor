Interrupt architecture
----------------------
- Implemented SSIP=1, MSIP=3, STIP=5, MTIP=7, SEIP=9, and MEIP=11.
- MIE is the local enable state; MIP is pending state. The implemented MIE and
  MIP views expose only these identities. MIDELEG permits only SSIP, STIP,
  and SEIP. SIE and SIP are masked views of delegated supervisor interrupts.
- M-mode software may set MSIP, SSIP, and STIP through MIP. SIP can clear
  delegated SSIP; SIP.STIP is read-only in this implementation. MTIP is owned
  by the timer comparison, and external pending state uses the bounded
  setInterruptPending interface. No external interrupt controller is claimed.
- Selection priority is MEI, MSI, MTI, SEI, SSI, STI. Delegated interrupts do
  not preempt M-mode. Machine-targeted interrupts preempt S/U regardless of
  MIE; same-privilege delivery observes the matching global enable.
- Interrupt entry sets mcause/scause bit 63 and the cause, preserves the
  interrupted PC, writes zero to the trap value CSR, updates the privilege and
  interrupt-enable stack, and does not retire the interrupted instruction.
  Pending sources are sampled at instruction boundaries and after xRET.

Timer, vectors, and WFI
----------------------
- Implemented a deterministic single-hart 64-bit mtime/mtimecmp device. The
  configurable default guest-physical map is mtimecmp=0x02004000 and
  mtime=0x0200BFF8 (QEMU virt CLINT register locations); this is only the two
  registers, not full CLINT/ACLINT support.
- Aligned 32-bit low/high and 64-bit register accesses are supported. Other
  widths, boundary overlaps, and unmapped addresses fault. The device is not
  ordinary RAM or executable memory; Sv39 and MPRV accesses translate before
  physical MMIO decoding, and the timer cannot be used as a page table.
- Virtual time advances one tick for each retired guest instruction. It does
  not use host wall time. The harness can add explicit ticks while WFI waits.
  mtime wraps modulo 2^64; MTIP is asserted exactly while unsigned
  mtime >= mtimecmp.
- mtvec/stvec implement Direct and Vectored. Exceptions always use BASE;
  vectored interrupts use BASE + 4*cause. Unsupported modes are WARL-ignored.
- WFI is a real retired instruction with observable waiting. No guest fetch or
  retirement occurs while waiting. A locally enabled pending interrupt wakes
  the hart even when global enable prevents trap delivery, keeping wake
  eligibility separate from actual interrupt entry. U-mode WFI and S-mode WFI
  with mstatus.TW set trap as illegal instructions.

Guest execution evidence
------------------------
- M-mode timer guest configures mtvec/mtimecmp and MTIE/MIE, receives MTIP,
  records mcause and the interrupted PC, reprograms the compare register,
  returns with MRET, and completes its resumed instruction sequence.
- S-mode guest configures delegation, takes and clears SSIP in its handler,
  returns with SRET, and verifies the resumed workload and CSR state.
- A separate guest distinguishes hardware MTIP (cause 7) from software
  presentation of STIP (cause 5): M-mode handles MTIP, sets MIP.STIP, S-mode
  handles delegated STIP, and an S-mode ECALL asks M firmware to clear it
  through SIP before SRET resumes the workload.
- WFI guest advances explicit virtual time while waiting, handles the timer
  event, resumes, and completes under a bounded scheduler loop.
- Sv39 guest executes translated S-mode code, fetches its translated interrupt
  vector, accesses translated data and mtimecmp MMIO, takes a delegated
  interrupt, returns with SRET, and resumes without an unintended page fault.
