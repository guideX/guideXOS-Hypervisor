Privilege and CSR coverage
--------------------------
- Modes M/S/U with U=0/S=1/M=3 encodings; reset in M; PC=guest base.
  Lower privilege entered architecturally (mstatus.MPP/SPP + mepc/sepc +
  MRET/SRET); no test backdoor setter exists. RV64 code is independent of
  IA-64 PSR/predicates/ICPU (unchanged standalone design).
- CSR matrix (addresses/behavior):
  mstatus 0x300 RW subset (MIE/MPIE/MPP/SPP/SPIE/SIE mask 0x19AA; MPP==2
    WARL-mapped to U) | sstatus 0x100 view (mask 0x122) into mstatus |
  misa 0x301 fixed 0x8000000000000100 (MXL=RV64, I only; writes ignored) |
  medeleg 0x302 RW bits 0-9 (M ECALL bit 11 hardwired 0) |
  mideleg 0x303 WARL 0 (no interrupts) |
  mie 0x304 / mip 0x344 WARL 0, sie/sip views 0 |
  mtvec 0x305 / stvec 0x105 Direct-only (low2!=0 writes ignored) |
  mscratch 0x340 / sscratch 0x140 full RW |
  mepc 0x341 / sepc 0x141 WARL 4B-aligned (low2 cleared) |
  mcause 0x342 / scause 0x142, mtval 0x343 / stval 0x143 full RW |
  mhartid 0xF14 read-only 0 |
  satp 0x180 Bare-only (nonzero MODE ignored, value stays 0; Bare is a
    direct byte-region mapping, not paging/PMP isolation).
  Unknown/unavailable CSRs trap illegal (cause 2), never silently succeed.
  Privilege (csr[9:8]) and read-only (csr[11:10]==3, honoring the
  no-write suppression) enforced; violations preserve rd and trap.
- Decoder fix: CSRRS/CSRRC with rs1==x0 now decode legal (were wrongly
  illegal), enabling `csrr` reads.

Trap/delegation behavior
------------------------
- Synchronous delivery with StepOutcome::Trap for: illegal instruction
  (cause 2, tval=faulting word), breakpoint (cause 3), instruction address
  misaligned (cause 0), instruction access fault (cause 1), load/store
  address misaligned (causes 4/6), load/store access fault (causes 5/7),
  ECALL from U/S/M (causes 8/9/11).
- Routing: M-mode traps stay in M; S/U traps with the medeleg bit set go to
  S (M ECALL never delegable). Entry saves xEPC (fault PC, WARL-aligned),
  xCAUSE, xTVAL (fault PC/addr, word, or 0), stacks MIE->MPIE/SIE->SPIE,
  records MPP/SPP, sets privilege and PC=tvec BASE. mtvec/stvec Direct only;
  vectored interrupts not advertised or implemented.
- MRET (M only): MIE=MPIE, MPIE=1, MPP=U, priv=MPP, PC=mepc. SRET (M/S,
  TSR hardwired 0): SIE=SPIE, SPIE=1, SPP=U, priv=SPP, PC=sepc. Misuse
  (MRET in S/U, SRET in U, nonzero rd/rs1 on SYSTEM ops) traps illegal.
- RISCV-1 EBREAK/C.EBREAK Halt convention preserved behind
  breakpointHaltEnabled (default true); when off, breakpoint traps flow
  architecturally. Legacy Illegal/FetchFault/MemoryFault enum values are
  retained for source compatibility but architectural faults now deliver
  traps (returned only when no guest image is loaded).
- Alignment policy (deterministic, documented): natural-width precise traps
  (1B never traps; 2B/4B/8B require modulo alignment); 32-bit instructions
  require 4B alignment (C execution disabled); failed instructions change
  neither registers nor memory (verified: rd preserved, no partial stores,
  JAL/JALR rd suppressed on misalignment, CSR rd/CSR suppressed on faults).

SBI functionality
-----------------
- Distinct firmware interception boundary (ISbiProvider, replaceable):
  S-mode ECALL first completes full M-mode trap entry (mepc/mcause/mtval,
  priv M, PC=mtvec); only then does the attached provider supply a0
  (error) / a1 (value). With no provider, the identical trap is delivered
  and guest registers are untouched, so ordinary ECALL semantics are never
  suppressed. Delegated (S-targeted) ECALLs never invoke SBI.
- Calling convention honored: a7=EID, a6=FID, a0-a5=args, a0=error,
  a1=value on return.
- SbiBaseProvider (EID 0x10) implements FID 0 GetSpecVersion (0x2000000,
  SBI v2.0), 1 GetImplID (0x47584F53 "GXOS"), 2 GetImplVersion (2),
  3 ProbeExtension (1 for 0x10 else 0), 4 GetMVendorID (0), 5 GetMArchID
  (0), 6 GetMImpID (0); other FIDs and non-Base EIDs return NotSupported
  (-2) and supports() reports false, so unsupported extensions are never
  advertised. No timer/IPI/fence/HSM/console/reset extension in this phase.

S-mode hello-world results
--------------------------
- Deterministic guest image (~0x700 bytes at 0x80000000, hand-assembled via
  in-test encoders, no toolchain at runtime): M setup installs mtvec/mepc/
  mstatus/medeleg and MRETs into S; S code runs RV64I arithmetic, writes
  "Hello from S-mode" (17 bytes) via 17x (ADDI+SB), performs four SBI Base
  ECALLs (GetSpecVersion, GetImplID, Probe 0x10, Probe 0x11) through the
  M-mode handler (mepc+=4; MRET, preserving SBI a0/a1), writes completion
  marker 1, and halts on EBREAK (documented harness stop; UART not
  required, harness reads guest memory).
- Execution evidence: halt in S-mode after >=4 S ECALL traps (all
  sbiHandled), S-mode entry observed, guest bytes "Hello from S-mode"
  read back from 0x80000400, stored SBI version 0x2000000 / impl
  0x47584F53 / probe 1 / probe-unsupported 0 / marker 1 all verified,
  S-mode arithmetic survivor t5==42, >40 Ok retirements, bounded in 500
  steps. Program runs from guest bytes through the production decoder
  (no host-side result emulation).
