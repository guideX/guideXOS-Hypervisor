  Decode-only coverage is NOT execution.

--- Phase RISCV-2: decoder fix + completed RV64I execution ---

Decoder fix (src/decoder/riscv_decoder.cpp):
- CSRRS/CSRRC with rs1==x0 are now decoded legal (read with no write side
  effect, e.g. `csrr t0, mepc`). Previously rejected as illegal, which
  contradicted the privileged specification. No other decode changed.

Instructions actually executed in RISCV-2 (RV64CPU::step, genuine semantics):
- RV64I complete: LUI, AUIPC, JAL, JALR, BEQ, BNE, BLT, BGE, BLTU, BGEU,
  LB, LH, LW, LD, LBU, LHU, LWU, SB, SH, SW, SD,
  ADDI, SLTI, SLTIU, XORI, ORI, ANDI, SLLI, SRLI, SRAI,
  ADD, SUB, SLL, SLT, SLTU, XOR, SRL, SRA, OR, AND,
  ADDIW, SLLIW, SRLIW, SRAIW, ADDW, SUBW, SLLW, SRLW, SRAW,
  FENCE, FENCE.I (documented single-hart no-ops),
  CSRRW, CSRRS, CSRRC, CSRRWI, CSRRSI, CSRRCI (with privilege/read-only/
  suppression rules), ECALL (trap + SBI interception), EBREAK (Halt when
  breakpoint interception is on, else breakpoint trap), MRET, SRET.
- W operations compute the 32-bit result and sign-extend to 64 bits; 64-bit
  shifts mask to 6 bits and W shifts to 5 bits; no host UB on shifts,
  signed overflow, or conversions (unsigned wraparound + explicit sign fill).
- Compressed execution stays deferred (Unsupported, never Ok), except
  C.EBREAK (Halt/trap as above). Compressed decode exists but executable
  compressed support is NOT advertised.

RV64I vs independently defined extensions (explicit split):
- RV64I (executed): all of the above integer/branch/load/store/fence/CSR/
  SYSTEM-privileged list.
- Zicsr (executed subset): the six CSR instructions with the CSR matrix in
  include/riscv_cpu.h (mstatus/misa/medeleg/mideleg/mie/mip/mtvec/mscratch/
  mepc/mcause/mtval/mhartid, sstatus/sie/sip/stvec/sscratch/sepc/scause/
  stval/satp/mcounteren/scounteren/time). satp accepts Bare (0) and Sv39 (8); ASIDLEN=0, so nonzero
  ASID writes are WARL-rejected and other MODE values leave satp unchanged.
  mstatus SUM/MXR/MPRV are writable; sstatus exposes SUM and MXR; TVM is
  hardwired zero. medeleg extends to bits 12/13/15. RISCV-4 implements the
  standard MSIP/MTIP/SSIP/STIP/MEIP/SEIP pending and enable identities,
  supported MIDELEG bits, and architectural MIP/SIP and MIE/SIE views.
  STIP is software writable in MIP because Sstc/stimecmp is not implemented;
  SIP.STIP is read-only. Unknown/unavailable CSRs trap illegal, never silently
  succeed.
- SYSTEM privileged (executed): ECALL/MRET/SRET with full trap semantics;
  WFI retires into an observable bounded waiting state and resumes for a
  locally enabled pending interrupt, including wake without a trap when the
  global enable masks delivery. U-mode WFI traps; S-mode WFI traps when
  mstatus.TW=1. SFENCE.VMA is decoded with funct7=0001001, funct3=000, rd=0
  and executed as an uncached-walker synchronization point. Each subsequent
  translation reads guest-physical PTEs again; U-mode SFENCE.VMA traps
  illegal. TVM is hardwired zero, so S-mode is allowed to execute it.
- RV64M (decode only, still Unsupported): MUL/MULH/MULHSU/MULHU/DIV/DIVU/
  REM/REMU/MULW/DIVW/DIVUW/REMW/REMUW.
- RV64A (decode only, still Unsupported): LR.W/SC.W/AMO* and LR.D/SC.D/AMO*.
- RV64F/D/V (not decoded, not executed).
- RV64C (decode only, execution deferred as above).

Explicitly unsupported operations (valid decode -> StepOutcome::Unsupported):
- All RV64M, all RV64A, all compressed except C.EBREAK.

Synchronous traps (StepOutcome::Trap, never silent):
- Illegal instruction (cause 2, tval = faulting word), breakpoint (cause 3),
  instruction address misaligned (cause 0), instruction access fault
  (cause 1), load/store address misaligned (causes 4/6), load/store access
  fault (causes 5/7), ECALL from U/S/M (causes 8/9/11), instruction/load/
  store page fault (causes 12/13/15, tval = faulting virtual address).
  Invalid PTE/permission failures raise page faults; page-table physical
  read/write failures and explicit physical-range failures after translation
  (or in M-mode/Bare) raise access faults. Legacy Illegal/
  FetchFault/MemoryFault outcomes are retained in the enum for source
  compatibility and are returned only when no guest image is loaded;
  architectural execution delivers traps.

--- Phase RISCV-4: asynchronous interrupt delivery and deterministic MTIMER ---

Interrupt identities and CSR state:
- Implemented causes: SSIP=1, MSIP=3, STIP=5, MTIP=7, SEIP=9, MEIP=11.
- mip exposes only those pending bits; mie independently controls their local
  enables. MIP software writes control MSIP, SSIP, and STIP. MTIP is timer
  owned. MEIP/SEIP are bounded source-injection inputs. SIE/SIP expose only
  delegated supervisor identities; MIDELEG accepts only SSIP/STIP/SEIP.
- Priority is MEI, MSI, MTI, SEI, SSI, STI. Delegated interrupts never
  preempt M-mode; machine-target interrupts preempt S/U independent of MIE;
  same-privilege delivery requires the matching global enable.
- Interrupt trap causes set RV64 mcause/scause[63], save the interrupted PC,
  clear the target global enable, and update MPP/MPIE or SPP/SPIE. Pending
  sources are rechecked at every instruction boundary and after xRET. Handler
  entry does not retire or alter the interrupted instruction state.

Machine timer and waiting model:
- The narrow single-hart MTIMER has 64-bit mtime and mtimecmp registers. Its
  default guest-physical map is mtimecmp=0x02004000 and mtime=0x0200BFF8, the
  corresponding QEMU virt CLINT register locations. The configurable mapping
  implements only these registers, not full CLINT/ACLINT.
- Naturally aligned 32-bit low/high accesses and 64-bit accesses are supported;
  other widths, partial boundary overlaps, and unmapped addresses fault. Device
  accesses take precedence over backing image bytes and are not executable or
  eligible as Sv39 page tables. S/U and MPRV accesses are translated before the
  physical MMIO decode.
- Virtual time advances one tick per retired instruction. It never uses host
  wall time. The harness may advance an explicit number of ticks while WFI is
  waiting. mtime wraps modulo 2^64 and MTIP follows unsigned mtime>=mtimecmp.
- mtvec/stvec accept Direct (MODE=0) and Vectored (MODE=1); unsupported modes
  are WARL-ignored. Exceptions always use BASE; vectored interrupts use
  BASE+4*cause. S-mode vector fetches continue through the Sv39 instruction
  path.

Guest execution evidence and RISCV-4 regression:
- The production CPU test executes a guest M-mode timer setup, MTIP handler,
  compare reprogramming, MRET, and resumed workload (24 increments plus a
  completion marker).
- A guest configures and services delegated SSIP through S-mode and clears it
  using SIP. A second guest demonstrates hardware MTIP handled in M, M-mode
  software presenting STIP through writable MIP, delegated S-mode service,
  and an S-mode ECALL to M firmware to clear read-only SIP.STIP.
- A WFI guest is advanced through explicit virtual ticks, services MTIP, and
  resumes within a bounded scheduler loop. Another real S-mode guest uses
  Sv39-translated code, vector, data, and mtimecmp MMIO accesses across an
  interrupt and SRET.
- test_riscv_interrupt_timer: 596 explicit runtime checks in Debug and Release.
  Covers CSR pending/enable/delegation masks and routing, priority, status/EPC/
  cause stacks, vector modes, MRET/SRET, timer compare/reprogram/rollover,
  MMIO widths/bounds/faults, WFI wait/wake, sync-trap preservation, SBI Base,
  and the integrated guests.
- Seven RISC-V CTest suites pass: decoder, fetch/decode, minimal execution,
  RV64I, privilege/SBI, Sv39, and interrupt/timer.

--- Phase RISCV-5: SBI TIME and supervisor timer service ---

SBI services and timer ownership:
- SBI Base behavior and version values are unchanged. SbiFirmwareProvider
  implements EID 0x10 and SBI TIME EID 0x54494D45, FID 0 only. The modern
  call receives an absolute RV64 deadline in a0, returns the signed SBI error
  in a0, and returns zero in a1. Unsupported EIDs/FIDs return
  SBI_ERR_NOT_SUPPORTED (-2). The legacy timer extension is not implemented.
- TIME is advertised by Base ProbeExtension only when a per-CPU
  SbiFirmwareProvider is attached to that same CPU. The Base-only provider
  continues to advertise Base but reports TIME unavailable.
- The CPU owns mtime, mtimecmp, the SBI-requested deadline, and its armed
  state. set_timer writes that CPU's mtimecmp and clears pending STIP. When a
  due machine timer interrupt enters M-mode, the provider disarms mtimecmp to
  UINT64_MAX before setting STIP. MTIP remains cause 7 and STIP cause 5; MTIP
  is not delegated. Rearming from an S-mode handler updates mtimecmp and
  clears the old STIP. UINT64_MAX disables practical future delivery.
- The provider executes as a host-side firmware service after architectural
  M-mode trap entry. Guest M-mode instructions at mtvec still execute and use
  MRET; S-mode SBI calls advance mepc in the guest M handler. The provider
  does not claim to execute firmware instructions on the guest's behalf.
- Virtual time policy remains one tick per retired guest instruction, with
  explicit harness ticks while WFI waits. S-mode reads CSR time only when
  mcounteren.TM is set; U-mode also requires scounteren.TM. No timer MMIO is
  exposed through this counter read, and Sstc/stimecmp are not advertised.

RISCV-5 executable guest evidence:
- test_riscv_sbi_time builds RV64I guest instruction streams and executes
  them through RV64CPU::step. Program A queries Base/TIME, reads time, calls
  sbi_set_timer, checks error/value results and preserves unrelated registers.
- Program B executes an S-mode timer handler and SRET after the M-mode MTIP
  service presents delegated STIP. Program C executes WFI and receives three
  distinct timer events; each handler uses SBI TIME to rearm, and the final
  UINT64_MAX call clears/disables the timer. The test harness explicitly
  advances deterministic virtual time while WFI is waiting.
- Program D repeats the three-event WFI workload with Sv39 enabled and
  non-identity S-mode instruction, handler, and data pages. It verifies
  translated vector fetch, guest-memory updates, virtual sepc, and return.
- Negative coverage includes unsupported EID/FID, Base-only/no provider,
  absolute/past/equal/future deadlines, STIP clearing and reprogramming,
  UINT64_MAX, MTIE/MIE/STIE/SIE gating, time CSR permission, two-CPU timer
  isolation, and bounded progress. Debug and Release each pass 158 runtime
  assertions in the focused suite.
- Seven pre-existing RISC-V CTest suites and the new SBI TIME suite pass in
  Debug. The seven-suite RISCV-4 baseline passed before edits. The focused SBI
  TIME suite also passes in Release.

Boot readiness inventory:
- RV64M: decoded but not executed. Required for targets compiled with M and
  for toolchains/runtimes that emit multiply/divide; optional for a deliberately
  RV64I-only smoke payload.
- RV64A: decoded but not executed. Required for SMP and guests/runtimes that
  use atomics; optional for the current single-hart, no-atomic guest proof.
- RV64C: decode foundation only; all compressed instructions except C.EBREAK
  remain Unsupported. Required if firmware or kernel binaries contain C
  instructions; optional when the target is built without C.
- ELF: the existing loader and validation tests are IA-64-specific; they do
  not load an EM_RISCV image into RV64CPU. ELF loading and RISC-V entry setup
  are mandatory for an ELF target, but a bounded raw-image proof can defer it.
- Firmware entry/layout: loadProgram starts at a caller-supplied base and the
  tests assemble their own M-mode boot instructions. A real firmware guest
  needs a documented reset PC, RAM/ROM map, entry arguments, and image loader.
- Device tree: no FDT generation or RISC-V FDT handoff/consumer exists. It is
  mandatory to describe devices to Linux/OpenSBI; a private fixed-map test
  image can defer it.
- UART/console: no RISC-V UART device is connected. It is needed for serial
  boot logs and interactive firmware, but not for a guest that reports through
  a bounded memory signature.
- SBI: Base and TIME are now available through the host-side per-CPU provider.
  IPI, RFENCE, HSM, SRST, PMU, and DBCN are unsupported. SMP needs the relevant
  IPI/HSM services; Linux and OpenSBI targets may require additional services
  according to their platform and configuration.
- Timer/platform: only single-hart mtime/mtimecmp using the deterministic
  retired-instruction clock is modeled. The M-provider translates due MTIP to
  STIP. There is no full CLINT/ACLINT, PLIC/APLIC/IMSIC, or external-device
  interrupt path. Linux hardware compatibility requires those platform
  contracts and the expected clock frequency/interrupt routing.

Recommended RISCV-6 target:
- Select a small, single-hart RV64I S-mode guest image with a documented M-mode
  entry contract and a memory-signature completion path. Add an RISC-V ELF
  loader only if ELF is part of that selected target; keep Linux/OpenSBI,
  multicore, external interrupts, and device emulation as later milestones.

--- Current executable status after Phase RISCV-6 ---

- The first independently assembled RV64 guest is checked in at
  tests/fixtures/riscv_guest/guest.bin. It is linked at 0x80000000 for
  rv64i_zicsr, LP64 soft-float, with relaxation and compressed instructions
  disabled. The source, linker script, LLVM build script, SHA-256 manifest,
  ELF metadata, instruction inventory, and disassembly are kept beside it.
- test_riscv_guest_boot loads the flat binary into the bounded RV64CPU guest
  RAM and executes it only through RV64CPU::step and the production decoder.
  The guest initializes M-mode state, executes MRET into S-mode, queries SBI
  Base through a real S-mode ECALL/M-mode trap, and writes a 72-byte signature
  at guest address 0x80008000. The full signature is checked by the harness.
- The fixture uses RV64I integer operations plus the implemented CSR/SYSTEM
  instructions. It emits no M/A/F/D/V or compressed instructions. RV64M/A
  remain Unsupported, RV64C execution remains deferred except C.EBREAK, and
  F/D/V remain unsupported. This is a test boot contract, not a Linux boot ABI.
- The flat image is sufficient because the linker fixes one load address and
  entrypoint, and the CTest guest needs no segment relocation or dynamic
  linking. Existing ELF loader/validator paths require EM_IA_64; RISC-V ELF64
  loading remains deferred until an ELF guest is selected.
- Nine RISC-V CTest suites pass in Debug. The focused guest-boot suite passes
  in Debug and Release with 167 explicit runtime checks. The boot report records
  the handoff, binary provenance, failure cases, IA-64 regressions, and the
  remaining requirements for an external firmware or OS payload.
