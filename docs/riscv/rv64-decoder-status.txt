  LB, LH, LW, LD, LBU, LHU, LWU, SB, SH, SW, SD,

- Zicsr (executed subset): the six CSR instructions with the CSR matrix in

--- Phase RISCV-4: asynchronous interrupt delivery and deterministic MTIMER ---

Interrupt identities and CSR state:
- Implemented causes: SSIP=1, MSIP=3, STIP=5, MTIP=7, SEIP=9, MEIP=11.
- mip exposes only those pending bits; mie independently controls their local
  enables. MIP software writes control MSIP, SSIP, and STIP. MTIP is timer
  owned. MEIP/SEIP are bounded source-injection inputs. SIE/SIP expose only
  delegated supervisor identities; MIDELEG accepts only SSIP/STIP/SEIP.
- Priority is MEI, MSI, MTI, SEI, SSI, STI. Delegated interrupts never
  preempt M-mode; machine-target interrupts preempt S/U independent of MIE;
  same-privilege delivery requires the matching global enable.
- Interrupt trap causes set RV64 mcause/scause[63], save the interrupted PC,
  clear the target global enable, and update MPP/MPIE or SPP/SPIE. Pending
  sources are rechecked at every instruction boundary and after xRET. Handler
  entry does not retire or alter the interrupted instruction state.

Machine timer and waiting model:
- The narrow single-hart MTIMER has 64-bit mtime and mtimecmp registers. Its
  default guest-physical map is mtimecmp=0x02004000 and mtime=0x0200BFF8, the
  corresponding QEMU virt CLINT register locations. The configurable mapping
  implements only these registers, not full CLINT/ACLINT.
- Naturally aligned 32-bit low/high accesses and 64-bit accesses are supported;
  other widths, partial boundary overlaps, and unmapped addresses fault. Device
  accesses take precedence over backing image bytes and are not executable or
  eligible as Sv39 page tables. S/U and MPRV accesses are translated before the
  physical MMIO decode.
- Virtual time advances one tick per retired instruction. It never uses host
  wall time. The harness may advance an explicit number of ticks while WFI is
  waiting. mtime wraps modulo 2^64 and MTIP follows unsigned mtime>=mtimecmp.
- mtvec/stvec accept Direct (MODE=0) and Vectored (MODE=1); unsupported modes
  are WARL-ignored. Exceptions always use BASE; vectored interrupts use
  BASE+4*cause. S-mode vector fetches continue through the Sv39 instruction
  path.

Guest execution evidence and RISCV-4 regression:
- The production CPU test executes a guest M-mode timer setup, MTIP handler,
  compare reprogramming, MRET, and resumed workload (24 increments plus a
  completion marker).
- A guest configures and services delegated SSIP through S-mode and clears it
  using SIP. A second guest demonstrates hardware MTIP handled in M, M-mode
  software presenting STIP through writable MIP, delegated S-mode service,
  and an S-mode ECALL to M firmware to clear read-only SIP.STIP.
- A WFI guest is advanced through explicit virtual ticks, services MTIP, and
  resumes within a bounded scheduler loop. Another real S-mode guest uses
  Sv39-translated code, vector, data, and mtimecmp MMIO accesses across an
  interrupt and SRET.
- test_riscv_interrupt_timer: 596 explicit runtime checks in Debug and Release.
  Covers CSR pending/enable/delegation masks and routing, priority, status/EPC/
  cause stacks, vector modes, MRET/SRET, timer compare/reprogram/rollover,
  MMIO widths/bounds/faults, WFI wait/wake, sync-trap preservation, SBI Base,
  and the integrated guests.
- Seven RISC-V CTest suites pass: decoder, fetch/decode, minimal execution,
  RV64I, privilege/SBI, Sv39, and interrupt/timer.

--- Phase RISCV-5: SBI TIME and supervisor timer service ---

SBI services and timer ownership:
- SBI Base behavior and version values are unchanged. SbiFirmwareProvider
  implements EID 0x10 and SBI TIME EID 0x54494D45, FID 0 only. The modern
  call receives an absolute RV64 deadline in a0, returns the signed SBI error
  in a0, and returns zero in a1. Unsupported EIDs/FIDs return
  SBI_ERR_NOT_SUPPORTED (-2). The legacy timer extension is not implemented.
- TIME is advertised by Base ProbeExtension only when a per-CPU
  SbiFirmwareProvider is attached to that same CPU. The Base-only provider
  continues to advertise Base but reports TIME unavailable.
- The CPU owns mtime, mtimecmp, the SBI-requested deadline, and its armed
  state. set_timer writes that CPU's mtimecmp and clears pending STIP. When a
  due machine timer interrupt enters M-mode, the provider disarms mtimecmp to
  UINT64_MAX before setting STIP. MTIP remains cause 7 and STIP cause 5; MTIP
  is not delegated. Rearming from an S-mode handler updates mtimecmp and
  clears the old STIP. UINT64_MAX disables practical future delivery.
- The provider executes as a host-side firmware service after architectural
  M-mode trap entry. Guest M-mode instructions at mtvec still execute and use
  MRET; S-mode SBI calls advance mepc in the guest M handler. The provider
  does not claim to execute firmware instructions on the guest's behalf.
- Virtual time policy remains one tick per retired guest instruction, with
  explicit harness ticks while WFI waits. S-mode reads CSR time only when
  mcounteren.TM is set; U-mode also requires scounteren.TM. No timer MMIO is
  exposed through this counter read, and Sstc/stimecmp are not advertised.

Boot readiness inventory:
- RV64M: decoded but not executed. Required for targets compiled with M and
  for toolchains/runtimes that emit multiply/divide; optional for a deliberately
  RV64I-only smoke payload.
- RV64A: decoded but not executed. Required for SMP and guests/runtimes that
  use atomics; optional for the current single-hart, no-atomic guest proof.
- RV64C: decode foundation only; all compressed instructions except C.EBREAK
  remain Unsupported. Required if firmware or kernel binaries contain C
  instructions; optional when the target is built without C.
- ELF: the existing loader and validation tests are IA-64-specific; they do
  not load an EM_RISCV image into RV64CPU. ELF loading and RISC-V entry setup
  are mandatory for an ELF target, but a bounded raw-image proof can defer it.
- Firmware entry/layout: loadProgram starts at a caller-supplied base and the
  tests assemble their own M-mode boot instructions. A real firmware guest
  needs a documented reset PC, RAM/ROM map, entry arguments, and image loader.
- Device tree: no FDT generation or RISC-V FDT handoff/consumer exists. It is
  mandatory to describe devices to Linux/OpenSBI; a private fixed-map test
  image can defer it.
- UART/console: no RISC-V UART device is connected. It is needed for serial
  boot logs and interactive firmware, but not for a guest that reports through
  a bounded memory signature.
- SBI: Base and TIME are now available through the host-side per-CPU provider.
  IPI, RFENCE, HSM, SRST, PMU, and DBCN are unsupported. SMP needs the relevant
  IPI/HSM services; Linux and OpenSBI targets may require additional services
  according to their platform and configuration.
- Timer/platform: only single-hart mtime/mtimecmp using the deterministic
  retired-instruction clock is modeled. The M-provider translates due MTIP to
  STIP. There is no full CLINT/ACLINT, PLIC/APLIC/IMSIC, or external-device
  interrupt path. Linux hardware compatibility requires those platform
  contracts and the expected clock frequency/interrupt routing.

--- Phase RISCV-8: static RISC-V ELF64 loading and execution ---

RISC-V ELF64 profile:
- A separate bounded loader lives in include/riscv/riscv_elf64_loader.h and
  src/riscv/riscv_elf64_loader.cpp. The IA-64 loader is not changed.
- Accepts ELF64, little-endian, current ELF version, System V/GNU OS ABI,
  EM_RISCV, ET_EXEC, a zero e_flags RV64IMA soft-float profile, and nonempty
  PT_LOAD segments. Section headers are optional and never determine placement.
- Requires a 64-byte ELF header, 56-byte program-header records, an in-file
  program-header table, and ordinary bounded program-header numbering.
  PN_XNUM, zero headers, and more than 64 headers are rejected.
- Limits input files to 16 MiB, load segments to 16, and total loaded memory to
  8 MiB. Rejects RVC, floating-point ABI, RVE, TSO, unknown ELF flags, ELF32,
  non-little-endian files, ET_REL, ET_DYN, PT_INTERP, PT_DYNAMIC, PT_TLS,
  PT_SHLIB, executable stacks, unknown program-header types, and runtime
  relocation/dependency requirements.
- For each PT_LOAD, bounds checks file and guest-RAM ranges, checks
  p_filesz <= p_memsz, power-of-two and offset/address-congruent alignment,
  requires p_paddr == p_vaddr, rejects overlaps and reserved-region collisions,
  copies p_filesz bytes, and zeroes the BSS tail. Entry must be four-byte
  aligned and contained in file-backed bytes of an executable PT_LOAD.
- The address policy is fixed-address identity placement: p_vaddr is the
  execution address, and p_paddr must equal it. No relocation or virtual-to-
  physical translation is performed by the loader.
- The complete plan, staged segment bytes, and rollback copies are prepared
  before the first write. A failed write attempts to restore all affected
  segment ranges. The CPU is reset and its PC set from e_entry only after all
  segment writes succeed. Timer MMIO overlap is rejected.

--- Phase RISCV-15: standard RV64 physical memory protection ---

- The CPU exposes PMP only when constructed with the explicit
  `PmpMachineProfile::StandardPmp16` profile. It implements 16 entries, a
  four-byte grain (G=0), and 54 pmpaddr bits encoding a 56-bit physical
  address. Historical fixtures retain the default `LegacyNoPmp` profile.
- RV64 `pmpcfg0` and `pmpcfg2`, plus `pmpaddr0` through `pmpaddr15`, use
  M-mode CSR access checks and instruction-level CSR read/write/suppression
  rules. Odd config banks and unavailable PMP registers are illegal. Reset
  leaves every entry OFF and unlocked. Reserved R=0/W=1 is WARL-mapped to
  read-only no-permission; reserved config bits read zero. Standard L-bit and
  locked-TOR predecessor address restrictions are implemented. Smepmp and
  `mseccfg` are not implemented or advertised.
- PMP matching supports OFF, TOR, NA4, and NAPOT with overflow-safe range
  decoding. Lowest-numbered partial matches deny the whole access. S/U
  unmatched accesses are denied when PMP exists; unmatched M-mode accesses
  pass, and unlocked entries do not restrict M-mode. MPRV selects effective
  data privilege. Instruction fetch uses the current privilege. PMP checks
  run after Sv39 translation and cover implicit supervisor PTE reads and A/D
  writes as well as guest data, atomics, and MMIO.
- The dedicated PMP suite covers CSR banks and privilege, reset/profile
  isolation, WARL handling, matching/priority, access traps, MPRV, Sv39 page
  table and final physical accesses, translated LR/SC/AMO atomicity, and
  denied UART, PLIC, and timer side effects. A guest-executed M-mode trap
  handler changes an unlocked PMP entry and MRETs to a previously denied S-mode
  load, which then succeeds. The OpenSBI guest validates actual S-mode
  firmware read/write/fetch denials, translated aliases, a page fault, and
  subsequent successful SBI Base and UART operations.
- The authentic OpenSBI v1.8.1 FW_JUMP image remains unchanged. Its own UART
  report identifies 16 PMP entries, 2-bit/four-byte granularity, and 54
  address bits. The S-mode domain denies access to adjacent firmware text and
  read/write regions through separate contiguous PMP entries; UART0 is
  explicitly granted to S-mode. See `phase-riscv-15-report.txt` for the exact
  ranges, trace, image hashes, validation results, and remaining platform work.
- Standard PMP is a physical-access control feature. It does not add the RISC-V
  hypervisor extension or establish isolation beyond the ranges and access
  modes measured in the RISCV-15 tests.
