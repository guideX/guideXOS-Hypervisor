UART model correction
---------------------
After Linux registered ttyS0, the first authentic write returned its full
length but drained only the initial transmitter batch. The RISC-V 16550 model
accepted only the receive-data interrupt enable (IER bit 0), while Linux's
8250 driver waits for transmitter-holding-register-empty service (IER bit 1)
to continue filling the transmitter. The model now supports IER THRE, reports
IIR 0x02, clears the indication when IIR is read, and asserts/deasserts the
existing level-sensitive PLIC source as TX service becomes pending. RX keeps
priority and existing UART behavior is retained.

The semantics match the TI TL16C2550 16550-compatible specification:
https://www.ti.com/lit/ds/symlink/tl16c2550.pdf
A direct UART/PLIC regression covers enabling THRE, IIR reporting and clearing,
source claim/completion/re-pending, successive TX bytes, and disabling THRE.
The only production emulator behavior change is the RISC-V UART model. No
instruction semantics, MMU, PMP, OpenSBI, Linux, or IA-64 implementation
changed.
