Restricted-domain design
------------------------
The new opt-in fixture is
tests/fixtures/riscv_opensbi_domain/platform.dts. It assigns hart 0 through the
CPU's opensbi-domain phandle to the supervisor-domain instance and hands off in
S-mode at 0x80200000 with the FDT at 0x82200000. The source FDT retains the
existing 64 MiB RAM, UART0, UART1, PLIC and ACLINT topology. OpenSBI's fixup
removes `/chosen/opensbi-domains` and disables the ACLINT node. In the observed
handed-off FDT, `/cpus/cpu@0` is disabled and still has its four-byte
`opensbi-domain` property. The pinned v1.8.1 fixup removes that property only
from enabled CPU nodes, so this disabled node is left unchanged. OpenSBI's
domain-selection log and final PMP state independently confirm that hart 0
entered the configured domain.

Permission bits are OpenSBI domain flags: M_R=0x01, M_W=0x02, M_X=0x04,
S/U_R=0x08, S/U_W=0x10, and S/U_X=0x20. The PMP profile remains
PmpMachineProfile::StandardPmp16: 16 entries, four-byte grain, 54 encoded
address bits, and a 56-bit physical address space. No broad grant is used to
fill the holes between regions.

Guest evidence
--------------
The authentic OpenSBI test uses StandardPmp16 with no host SBI provider. It
checks that OpenSBI selects the FDT-assigned hart domain and writes PMP CSRs
using guest instructions. The guest requests SBI Base and SBI TIME through
OpenSBI, then tests bare firmware load/store/fetch denial, a direct denied
mtimecmp write, denied mtime read, unmatched device and RAM accesses, an
unassigned physical address, and an out-of-window UART write.

Sv39 coverage includes permitted guest code and RAM, a physical firmware
mapping and alias, denied fetch, a denied page-table read through a protected
firmware pointer, a denied implicit A-bit update to the S-read-only PTE page,
an execute-only page fault, and a translated mtimecmp store. The guest trap
handler records cause, stval and sepc for all 16 expected faults and resumes
only at designated labels. The host correlates recorded PCs with PMP physical
access events and checks that denied device accesses have no MMIO event.
The guest also stores and reloads 0x1d3d5a7b9cbed0f2 through the identity
mapping 0x83e02000->0x83e02000 and 0xa55a1234deadbeef through the nonidentity
mapping VA 0x40006000->PA 0x83e01000. S-mode PMP trace records both loads and
stores with their virtual and physical addresses, and the host checks the
resulting physical RAM values.

The authorized path receives from UART0 and transmits the full guest message,
receives an independent UART1 byte, configures the PLIC S-context, and claims
and completes the UART1 source. It handles a real external interrupt and an
SBI TIME timer interrupt, then verifies that OpenSBI disarms the machine
comparator. The UART/PLIC trace proves guest S-mode instructions touched the
authorized regions.

A separate M/S transition guest uses real M-mode pmpcfg0 instructions. It
starts with an unlocked exact 8-byte NAPOT region denied, traps an S-mode load,
grants read access, executes SFENCE.VMA, verifies a successful S-mode load,
revokes access, executes SFENCE.VMA, and recovers from the second S-mode load
fault. The initial deny setup also executes SFENCE.VMA. The bounded trace
records three M-mode fence instructions and the deny/grant/deny CSR values.
The MMU walker does not cache translations; SFENCE.VMA is architecturally
executed and traced, but no TLB invalidation effect is claimed.

The existing RISCV-15 PMP suite continues to cover L-bit write suppression,
locked TOR predecessor behavior, reset clearing locks, MPRV, atomics, denied
UART/PLIC/timer side effects, and per-CPU PMP state. Standard PMP's unlocked
entries do not constrain M-mode, and this phase does not implement Smepmp.

Limitations and next phase
--------------------------
This is a single-hart physical-access policy proof, not a hypervisor, secure
virtualization boundary, or complete platform-isolation claim. The full PLIC
window is authorized; firmware/SBI runtime scratch remains machine-only;
standard PMP gives unlocked M-mode access; no TLB is implemented; and FDT
allocation is a fixed test reservation rather than a general runtime allocator.
No Linux, U-Boot, SMP, SBI IPI/HSM/RFENCE, storage, network, or virtio path was
attempted.

Recommended RISCV-17: make the single-hart boot contract and memory reservation
rules explicit at platform initialization, add machine-readable effective
domain/PMP comparison output, and extend safe transition tests to locked-entry
rejection and reset recovery without widening any range. Keep Linux and
multi-hart work out of scope until those contracts and device mappings are
validated across more than the focused fixture.
