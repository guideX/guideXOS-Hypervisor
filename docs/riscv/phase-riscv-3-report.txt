Audit findings and fixes
------------------------
The committed RISCV-3 implementation was present, but review found gaps in
several acceptance-critical details. This follow-up corrected them:
- SFENCE.VMA now uses the architectural encoding (funct7=0001001,
  funct3=000, rd=0). The reserved 0001000 encoding is rejected.
- S-mode instruction fetch from a U page always faults, even with SUM=1.
  SUM only permits S-mode loads/stores to U pages. MXR permits loads from
  execute-only pages at both S and U effective privilege.
- sstatus now exposes and writes its SUM and MXR fields. TVM remains
  hardwired to zero and is not advertised as implemented.
- PTE validation rejects all unsupported/reserved bits 63:54, W without R,
  and U/A/D set in a non-leaf PTE. Leaf detection includes R, W, or X, so
  execute-only leaves work correctly. RSW remains software-owned.
- Superpage alignment now checks all PPN[0] bits for 2 MiB pages and all
  PPN[1:0] bits for 1 GiB pages. Failed A/D-bit writeback cannot be reported
  as a successful translation.
- The Sv39 guest proof now constructs its page tables using M-mode SD
  instructions inside RV64CPU::step, executes SFENCE.VMA, and MRETs into
  S-mode. The S-mode hello guest reads its message back through a translated
  load before recording its marker.

Implemented behavior
--------------------
- Translation modes: Bare identity translation and Sv39 (satp.MODE=8).
  Unsupported modes retain the previous WARL value. ASIDLEN=0; nonzero ASID
  writes are rejected, and no ASID isolation is claimed.
- Guest physical memory is a bounded byte vector mapped at a guest physical
  base. Page-table reads and A/D writes use guest physical addresses directly;
  page-table entries are never recursively translated and guest VAs are never
  treated as host pointers. Out-of-range page-table physical reads/writes
  raise access faults; a valid translation to an unavailable physical target
  reaches the CPU's explicit access check and also raises an access fault.
- The walker has a fixed maximum depth of three and supports 4 KiB, 2 MiB,
  and 1 GiB leaves. It validates Sv39 canonical addresses, PPN extraction,
  page offsets, superpage alignment, and guest physical bounds at each page-
  table read; explicit data/code physical accesses have their own bounds check.
- PTEs use the Sv39 V/R/W/X/U/G/A/D/RSW and PPN fields. W-without-R,
  invalid encodings, malformed non-leaf U/A/D, unsupported high extension
  bits, and misaligned superpages raise access-type-specific page faults.
- Permissions cover S/U effective privilege, SUM, MXR, and MPRV/MPP for
  explicit M-mode data accesses. M-mode instruction fetch and M-mode data
  accesses with MPRV=0 or effective MPP=M bypass S-stage translation. A page
  fault from M-mode remains in M-mode even if MPRV selected S or U for data.
- Hardware-style A/D updates are used for the single-hart model: A is set
  after each qualifying successful access and D after a successful store.
  The page-table update executes synchronously in the same CPU step against
  guest physical memory, so no modeled hart can interleave with it. This is
  not an Svade fault-on-clear implementation or a hybrid policy.
- SFENCE.VMA is decoded and privilege checked. The walker is uncached and
  each translation rereads guest physical PTEs; the instruction therefore
  acts as the single-hart synchronization point without cached entries to
  invalidate. U-mode traps illegal. TVM=0, so S-mode is permitted.
- Page faults use causes 12/13/15 and the faulting virtual address in
  mtval/stval. Access faults and natural-misalignment faults remain distinct.
  Page-table access failures and inaccessible translated physical targets use
  access-fault causes 1/5/7 rather than page-fault causes.
  Existing delegation routes eligible S/U-origin faults to S-mode; M-origin
  faults are never delegated. Faulting fetch/load/store state remains precise.

Guest execution evidence
------------------------
- Program A's M-mode guest writes root, middle, and leaf PTEs to guest
  physical RAM, including a code mapping from VA 0x40000000 to PA 0x80010000,
  a separate writable data mapping from VA 0x40001000 to PA 0x80020000, a
  handler mapping, and page-table aliases. It writes satp, executes the
  architectural SFENCE.VMA encoding, and MRETs to S-mode.
- The S-mode guest fetches and executes through the virtual code mapping,
  performs arithmetic, writes Hello from Sv39 through translated stores,
  reads the first byte back through a translated load, and writes a success
  marker derived from that load. The harness verifies the message and marker
  at the distinct physical DATA_PA and checks the guest-created PTEs.
- Program C starts with DATA_VA invalid. Its S-mode store raises cause 15;
  the S handler observes stval=DATA_VA and sepc at the faulting store,
  installs the leaf mapping through a translated page-table alias, executes
  SFENCE.VMA, and SRETs. The retry succeeds, the guest continues to its
  deterministic EBREAK halt, and the harness checks the final data, marker,
  trap state, PC sequence, and retired instruction count.
- Proof code uses the production RISC-V decoder and RV64CPU::step. Test-only
  direct privilege setup is used for focused unit cases, not to mark either
  guest proof successful.

Remaining gaps and RISCV-4 recommendation
-----------------------------------------
- No TLB, Sv48/Sv57, ASID support, SMP, timers, or interrupt delivery.
- TVM and machine/supervisor interrupt sources remain hardwired off.
- RV64M/A/F/D/V execution, full compressed execution, ELF boot flow, UART,
  virtio, device tree, and complete SBI services remain out of scope.
- Linux/OpenSBI boot is not supported or claimed. RISCV-4 should independently
  add timer/interrupt delivery and the required platform/SBI groundwork before
  attempting firmware or operating-system boot.
