guideXOS Hypervisor — Phase RISCV-25 Report
Authentic Linux v6.12 initcall progression and userspace-readiness frontier

Outcome: A. Authentic OpenSBI and the unchanged Linux v6.12 Image reproduced
the accepted RISCV-24 80-million-retirement state, crossed the unfinished slab
allocation, completed the remaining observed kernel initialization path,
prepared the namespace, freed init memory, and tried all four default init
paths. Each kernel_execve returned -ENOENT. Linux then emitted its explicit
"No working init found" panic. No userspace instruction ran. This is a missing
init/root-filesystem boot-environment requirement, not an observed CPU, SBI,
PMP, or device-emulation failure and not a claim of completed boot.

returns, callback symbols, guest retirements, and the surrounding observed
kernel_init_freeable return path. The source control flow is in Linux v6.12
init/main.c: https://github.com/torvalds/linux/blob/v6.12/init/main.c

Linux entered run_init_process, try_to_run_init_process, and kernel_execve four
times for /sbin/init, /etc/init, /bin/init, and /bin/sh. Each kernel_execve
returned a0=-2 (-ENOENT). The final UART line is:

  Kernel panic - not syncing: No working init found. Try passing init= option to kernel. See Linux Documentation/admin-guide/init.rst for guidance.

No userspace transition or U-mode retirement occurred. devtmpfs was mounted,
but the run supplied neither an initramfs nor a root filesystem containing an
init executable. This is the first demonstrated terminal boot requirement;
there is no evidence that expanding the emulator's device or ISA model would
resolve it.

Initcalls and task switches
---------------------------
At the exact 80M checkpoint, aggregate initcall accounting was 364 entries,
363 matched completions, 353 zero returns, 10 nonzero returns, and one active
callback. Of the detail cap of 256, 256 were retained and 108 were omitted.
By the terminal panic, all 386 entries had matching completions: 376 returned
zero and 10 nonzero. No invocation remained active; 256 detail records were
retained and 130 omitted. Counts are aggregate observer results; dropped
details are not treated as missing executions or inferred return values.

The ten observed nonzero callbacks were cacheinfo_sysfs_init (-ENOENT), and
clk_starfive_jh7100_driver_init, cpufreq_dt_platdev_init,
jh7100_reset_driver_init, jh7110_pll_driver_init, jh7110_syscrg_driver_init,
renesas_soc_init, sifive_ccache_init, sun50i_iommu_driver_init, and
sunxi_sram_driver_init (each -ENODEV). These are callback return values, not
automatically platform failures. In the pinned Linux sources,
cacheinfo_sysfs_init propagates the cache hotplug callback's -ENOENT when no
cache leaves are described; cpufreq_dt_platdev_init returns -ENODEV when the
root compatible/CPU OPP data is not on its allowlist; sifive_ccache_init and
renesas_soc_init return -ENODEV when their matching device-tree nodes are
absent. The StarFive clock/reset, Allwinner IOMMU, and SRAM initcalls use
`builtin_platform_driver_probe` for platform-specific compatible devices; no
such hardware is described by this machine FDT. These optional setup results
are separate from architectural or generic device-emulation failures. The
kernel proceeds through initcall completion, namespace preparation, initmem
cleanup, and init attempts without a related architectural failure.

At 80M there were 1,321 switch entries and 1,321 confirmed distinct completed
task switches; 512 details were retained and 809 omitted. At the stop there
were 1,337 entries and 1,337 confirmed distinct completions; 512 retained,
825 omitted. Saved and restored contexts were observed on all 1,337 operations.
There were 21 distinct previous-task identities and 20 next-task identities;
no active, incomplete, uncertain, or untracked switch remained. The counters
do not imply a userspace process.

UART, SBI, timer, and traps
--------------------------
The full S-mode Linux UART0 capture is 7,157 bytes. It preserves the 6,367-byte RISCV-24 prefix and
adds 790 bytes, including IOMMU policy, USB, ALSA, clocksource selection,
PCI/workingset, SBI PMU capability, debug page-table validation, unused clock
and power-domain shutdown, no soundcards, an initial-console warning,
devtmpfs mount, initmem release, four init attempts, and the exact panic line.
UART1 remains silent. Firmware pre-handoff and Linux console bytes retain their
separate attributions.

Linux made 3,685 SBI calls: 20 Base, 3,589 TIME, and 76 PMU requests. Every
call returned and S-mode resumed. All 3,589 TIME requests succeeded. Of 76 PMU
calls, 24 succeeded; 52 returned expected optional-extension errors: 50
SBI_ERR_NOT_SUPPORTED from FID 2, one SBI_ERR_NOT_SUPPORTED from FID 7, and
one SBI_ERR_INVALID_PARAM from FID 1. No PMU implementation was added.

The deterministic 10 MHz virtual mtime advances one tick per retired guest
instruction. mtime advanced from 0x00bb7ca3 at handoff to 0x05ba112f at stop;
mtimecmp ended at 0x05b9c89f. TIME saw 1,795 disabled deadlines and 1,794 future deadlines;
none was expired or decreasing, and every request succeeded. There were 1,794
machine timer interrupts and 1,793 supervisor timer interrupts. Exactly one
final MTIP had no following STIP because execution stopped at the terminal
panic; the other observed timer pairings reconcile. Trap accounting recorded
11,306 transitions, 11,305 matched handler entries/returns, zero active
handlers, maximum nesting 2, largest handler 6,012 instructions, and zero
dropped trap details. The 9,512 MRET and 1,793 SRET retirements account for all
11,305 matched handler returns. No PMP-denied event was recorded.
